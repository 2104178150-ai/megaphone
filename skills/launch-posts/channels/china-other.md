# 其他中文渠道：知乎、B 站、开源中国、少数派、Gitee

> **English summary:** Long-tail Chinese channels — slower than V2EX or 即刻, but content
> there keeps being found through search. Answer existing Zhihu questions honestly (and
> disclose you're the author), make demo videos for Bilibili, list the project in
> OSChina's software directory, write "how I use it" pieces for sspai, and mirror the
> repo on Gitee for users with slow GitHub access.
>
> 最近核对：2026-10。这些是长尾渠道，见效比 V2EX 和即刻慢，但内容会被搜索持续找到。发布前请看各平台当前规则。

## 知乎

- **回答已有的问题**：只挑你的项目确实能解决提问者问题的问题
  （例如「有哪些好用的开源 XXX 工具？」「如何推广自己的开源项目？」）。先认真回答问题本身，
  再提到你的项目，并**说明自己是作者**。
- 专栏文章写法和掘金文章类似：问题 → 思路 → 结果 → 链接。
- 不要在很多问题下贴同一段回答。

## B 站

- **视频演示和教程**：3–8 分钟的「从零用 <名字> 做 X」，或 1 分钟的快速演示。开发者和 AI 工具类内容有活跃的观众。
- 仓库链接放在视频简介里，再置顶一条带链接的评论。
- 加上分段（章节）和清晰的封面标题，方便被搜索到。

## 开源中国（OSChina）

- 有一个很多国内开发者会浏览的**开源软件库**（[oschina.net/project](https://www.oschina.net/project)）和资讯栏目。
  找到收录项目的入口（投递 / 收录），按它的格式提交。
- 适合长尾曝光，尤其是面向国内企业用户的项目。

## 少数派（sspai）

- 适合**面向普通用户的应用和效率工具**，不适合代码库。社区写作区接受用户投稿，
  一篇真诚的「我是怎么用它的」配截图，比发布公告更合适。

## Gitee

- 国内的代码托管平台。在 Gitee 上放一个**仓库镜像**，能照顾访问 GitHub 慢的用户；Gitee 也有自己的推荐项目栏目。
  以 GitHub 仓库为准，并在两边 README 里都写清楚。

## 常见坑

- 所有平台发同一份文案 → 每个平台都有自己的格式，要改写。
- 回答里不说明作者身份 → 容易被举报为软广。
