# 掘金

> **English summary:** A large Chinese community of working engineers (frontend, mobile,
> backend). Long-form technical articles are the main format; 沸点 is for short posts.
> Write "how I built it" with real technical depth and let the project be the natural
> result, not an ad. The site's basic rules (掘金基本法) welcome original articles and open
> source and reject false or plagiarised content and titles. **Juejin's written rules treat
> AI-generated technical content posted directly as a plagiarism-type violation (never
> recommended), so articles and 沸点 are author-written from a fact sheet.** Promotional articles aren't
> recommended and can be deleted; "open-source tool introductions" are an official topic.
> Timing is a heuristic.
>
> 最近核对：2026-10-16。官方规则都在免费小册《如何使用掘金社区》里（需要在浏览器里打开）：
> [《掘金基本法》](https://juejin.cn/book/6844733795329900551/section/6844733795367649288)、[《掘金社区内容的标准和规范》](https://juejin.cn/book/6844733795329900551/section/6844733795380232199)、
> [《掘金的内容审核和推荐规则》](https://juejin.cn/book/6844733795329900551/section/6876001660431400967)、[《掘金社区行为规范&处罚措施》](https://juejin.cn/book/6844733795329900551/section/6844733795380232200)、
> [《如何让你的文章获得更多曝光和认可》](https://juejin.cn/book/6844733795329900551/section/6844733795380232206)。「规则与习惯」里注明出处的是官方规则，
> 格式、时机和模板是社区习惯。

## 适合什么项目

国内一线工程师聚集的大型技术社区，前端、移动端、后端的读者尤其多。主要形式是**长篇技术文章**，
**沸点**用来发短动态。文章会被搜索引擎收录，能持续带来读者。适合有技术看点的项目：实现思路、
架构取舍、性能优化讲得出东西的，比纯功能介绍更合适。

## 规则与习惯

- **不要直接发 AI 生成的文章（成文规则）**：[《掘金社区行为规范&处罚措施》](https://juejin.cn/book/6844733795329900551/section/6844733795380232200)
  把「利用ChatGpt等AIGC工具，发布文章」列为抄袭行为（「人工智能生成技术文章，或者其他技术体裁内容在掘金直接发布」）。这类文章「全部不推荐」，会被
  归到笔记里；拿去参加掘金活动的，还会被取消资格、账号降权。所以掘金长文由作者自己写：Megaphone 只给
  事实清单和文章结构，正文用作者自己的话写，代码、数据、踩过的坑都要是真的。沸点也一样，下面的沸点模板只是格式示意。
- **掘金基本法**：倡导分享原创文章、开源项目，基于技术和事实分享有价值的信息；不欢迎错误、虚假、
  抄袭的内容或标题。
- 标题尽量简单、不夸张，禁止标题党（[《掘金社区内容的标准和规范》](https://juejin.cn/book/6844733795329900551/section/6844733795380232199)）。标签要
  贴合内容：官方说明，选了关注量大但不对口的标签（如「前端」），文章热度会很低，很快就会减少推荐
  （[《如何让你的文章获得更多曝光和认可》](https://juejin.cn/book/6844733795329900551/section/6844733795380232206)）。
- **开源项目可以写，推广文不行**：官方推荐题材里有「开源工具介绍」；推广类文章（广告、SEO 等）不推荐，
  一经发现会被删除（《内容审核和推荐规则》《行为规范&处罚措施》）。推荐一般在发布后 24 小时内完成，
  好文章可以发到沸点「好文推荐」圈子自荐。
- 文章主体讲技术，项目顺带出场，仓库链接在开头和结尾各放一次就够了（习惯）。加个人微信、拉群、推广产品
  一律禁止，带二维码的文章一律不推荐，只允许用文字引导关注公众号（[《掘金的内容审核和推荐规则》](https://juejin.cn/book/6844733795329900551/section/6876001660431400967)）。
- **分类**从 后端 / 前端 / Android / iOS / 人工智能 / 开发工具 / 代码人生 / 阅读 里选一个（「开源」是标签，
  不是分类）；**标签**挑具体、对口的：普通账号只能加 1 个标签（掘金优秀作者 2 个，以编辑器为准），选最对口的具体
  技术或「开源」，文章才会推给对口的读者。

## 格式

- **长文**：「我是怎么用 X 实现 Y 的」、架构拆解、性能对比、踩过的坑。要有能直接运行的代码块、
  架构图、优化前后的数据。
- **沸点**：一两句话 + 截图 + 文章链接，适合发布当天告诉关注你的人。
- 不要把 README 原样贴过来：文章要讲 README 里没有的东西（为什么这么设计、踩了什么坑）。

## 时机

（经验，没有平台数据；北京时间）工作日上午 9:00–11:00 和午休前后读的人多。文章会被搜索引擎收录、
长期带来读者，所以发布时间不如标题和标签重要。文章和沸点可以同一天发，先发文章，再用沸点带一下。

## 模板

文章结构（**提纲**，正文由作者自己写，见上面的成文规则）：

```
标题：我做了一个 <名字>：<解决什么问题>（附实现思路）

一、背景：遇到了什么问题
二、现有方案为什么不够
三、实现思路（关键代码 / 架构图）
四、效果（截图、数据）
五、怎么用（一行命令）+ 仓库地址
六、还没做好的地方 & 后续计划
```

沸点（格式示意，用自己的话写）：

```
刚开源了一个小工具 <名字>：<一句话它做什么>。实现思路写在这篇文章里：<文章链接>（配截图）
```

## 常见坑

- 直接发 AI 生成的文章 → 官方算抄袭类违规，全部不推荐。
- 披着文章外衣的短广告 → 官方不推荐，严重的会被设为仅自己可见或删除，评论区也不友好。
- 把 README 原样贴过来 → 读者没有理由读这篇文章。
- 标题夸大（「吊打」「秒杀」）→ 官方禁止标题党，评论区也会挑刺。
