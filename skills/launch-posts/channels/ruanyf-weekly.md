# 阮一峰《科技爱好者周刊》

> **English summary:** One of the most-read Chinese tech newsletters, published every
> Friday. Submit articles, software or resources — including your own project — by
> opening an issue on github.com/ruanyf/weekly. Recent self-submissions use titles like
> 「【开源自荐】名字：一句话」, and there are dozens of them a day, so the title has to be
> clear at a glance. Submitting Monday to Wednesday for that Friday is a heuristic, not a rule.
>
> 最近核对：2026-10-15，依据 [ruanyf/weekly 的 README](https://github.com/ruanyf/weekly) 和近期 issue。

## 适合什么项目

国内阅读量最大的科技周刊之一，**每周五发布**，内容覆盖面很广：文章、工具、资源，以及对广大技术读者
有用或有趣的开源项目。读者不全是程序员，普通用户也能用的工具同样合适。

## 规则与习惯

- README 写明欢迎投稿**文章、软件、资源**，方式是**提交 issue**。可以推荐自己的项目，是否收录由作者决定。
- 一个项目只开一个 issue。
- issue 区很热闹：2026-10-13、10-14 两天，标题带「荐」的新 issue 每天三四十个（按 GitHub API 的
  UTC 日期统计）。标题要让人一眼看懂是什么。
- issue 里用中文介绍，即使项目本身是英文的。

## 怎么投稿

在 [github.com/ruanyf/weekly/issues](https://github.com/ruanyf/weekly/issues) 新开一个 issue，需要 GitHub 账号。

## 格式

- **标题**：近期自荐 issue 大多写成 **「【开源自荐】名字：一句话介绍」**（也有【工具自荐】【网站自荐】），
  照着写，方便作者一眼识别。
- **正文**：先翻几期周刊，看工具是怎么被介绍的：简短、客观，一两句话加一个链接。照这个风格写，
  作者更容易直接采用。这是周刊会印出来的介绍，不需要写「还不支持什么」。
- **一句非专业读者也能看懂的价值**：读者面很广。
- **链接对国内读者友好**（仓库 + 在线体验），尽量避免需要特殊网络才能打开的页面。

## 时机

- 周刊每周五发布（README）。截稿时间没有公开。
- （经验，没有官方说明）周一到周三提交，有机会赶上当周五那一期；收不收、哪一期收，都由作者决定。
- 投稿不必等发布周，但链接要已经能打开、能试用。

## 模板

```
标题：【开源自荐】<名字>：<一句话介绍>

<名字>（<仓库链接>）是一个 <类别>，可以 <做什么>，适合 <谁>。

亮点：<最特别的一点>。
在线体验 / 安装：<链接或一行命令>
协议：<开源协议>

谢谢阮老师！
```

## 常见坑

- issue 写成长篇推广文 → 按周刊会印出来的样子写。
- 同一个项目开好几个 issue。
- 标题只有项目名、看不出是什么 → 淹没在当天几十个自荐里。
- 链接国内打不开 → 作者和读者都点不开。
