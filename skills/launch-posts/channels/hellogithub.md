# HelloGitHub 月刊

> **English summary:** A monthly Chinese showcase of interesting, beginner-friendly open
> source, published on the 28th. Self-submissions are welcome via the 「提交项目」 button
> on hellogithub.com (log in with GitHub or WeChat). The form has three fields: repo URL,
> a one-line title (don't repeat the project name), and a 10–300 character description.
>
> 最近核对：2026-10，依据 [HelloGitHub README](https://github.com/521xueweihan/HelloGitHub) 和
> [hellogithub.com](https://hellogithub.com) 的提交表单。

## 适合什么项目

HelloGitHub 分享**有趣、入门级的开源项目**，也收录开源书籍、实战项目和企业级项目。**每月 28 号**
以月刊形式发布，同时发在 GitHub、官网和微信公众号。被收录后会带来持续的中文读者，还可以在 README
里挂上「Featured｜HelloGitHub」徽章。最近收录了不少 AI 技能包、Agent 工具类项目。

## 怎么投稿

1. 打开 [hellogithub.com](https://hellogithub.com)，点右上角 **「提交项目」**。
2. 登录：支持 **「通过 GitHub 登录」** 和 **「通过 WeChat 登录」**（微信扫码），不需要单独注册。
3. 填写表单，只有三栏：
   - **项目地址**：只接受 GitHub 上的开源项目。
   - **标题**：一句话介绍项目。网站展示时会自动在前面加上项目名，变成「项目名—标题」，
     所以**标题里不要再写项目名**。
   - **描述**：**10–300 个字符**。说清楚它是什么、解决什么痛点、用了什么技术、支持哪些功能、
     适合什么场景。表单提示写着：描述通俗易懂、符合要求，可以提高通过率。
4. 提交后由编辑审核，不保证收录，也没有公开的审核清单。

## 怎样更容易被收录

- 有**中文 README**，或者 README 里有中文说明，读者首先看中文。
- README 开头就讲清楚「是什么 / 给谁用 / 怎么一步上手」。
- 有截图或 GIF。
- **有趣或者有学习价值**：月刊偏爱好玩、值得一学的项目，而不只是企业基础设施。
- 在持续维护：最近有提交，有 Release。
- 参考网站上已收录项目的描述写法：一般以「这是一个……」或「该项目是……」开头，两三句话，平实具体。

## 模板

```
项目地址：<GitHub 仓库链接>

标题：<不含项目名的一句话，例如「帮开源项目做好发布的工具」>

描述（10–300 字）：这是一个 <类别>，可以 <做什么>。它 <核心功能 1>，<核心功能 2>，
支持 <技术或平台>。适合 <谁> 在 <什么场景> 使用。在线体验：<链接>
```

## 常见坑

- 只有英文 README、没有任何中文说明 → 编辑和读者都更难判断。
- 还没有能试用的东西就投稿 → 「有趣」要靠上手试才能判断。
- 每个月重复投同一个项目 → 投一次就够，有重大更新再投。
- 描述超过 300 字 → 表单不让提交，先压缩。
