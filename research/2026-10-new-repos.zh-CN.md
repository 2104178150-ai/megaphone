# 362 个新开源项目告诉我们的事

[English](2026-10-new-repos.md) | 简体中文

2026 年 10 月。我们用 Megaphone 的 [21 项检查](../skills/launch-audit/rubric.md)，给 2026 年 8–9 月新建的
362 个公开 GitHub 仓库打了分，按 star 数分四档，想看看「被人看到的新项目」和「没人看的」差在哪。

**结论先说**

- **被看到的项目，看起来更像「做完了」。** 和 5–99 星的项目比，100 星以上的项目更常有：首屏截图或动图
  （68% 对 40%）、快速开始（89% 对 74%）、开源协议（96% 对 81%）、发过版本（82% 对 63%）、徽章（66% 对 38%）、
  社区入口（51% 对 27%）、Issue 模板（50% 对 28%）、第二语言的 README（33% 对 15%）。
- **有些东西两边完全没差别：** 仓库简介、一句话介绍、README 长度、功能列表、靠前的代码块、「为什么用它」、行为准则。
- **分数和 star 数只是弱相关**（Spearman ρ = 0.34）。100 星以上的项目三个里有一个拿到 80 分以上，100 星以下的七个里才有一个。
- **小心「有星没 fork」的仓库。** 20–99 星、最近更新的 300 个新仓库里，有 67% 到 88% 一个 fork 都没有（一小时内搜了三次）。
  我们看过的这类仓库，多数是名字相似的「游戏修改器」「mod」「vault」，每个 50–70 星。

## 哪些有差别，哪些没有

100 星以上的 200 个仓库，对比 5–99 星的 162 个。*p* 是双侧 Fisher 精确检验；这样的样本量下，
差距小于 10 个百分点左右的，可能只是偶然。

| 检查项 | 100 星以上 | 5–99 星 | *p* |
|---|---|---|---|
| 首屏有截图、动图或视频 | 68% | 40% | <0.001 |
| 徽章 | 66% | 38% | <0.001 |
| 社区入口（Discussions，或 Discord / Telegram / 微信群链接） | 51% | 27% | <0.001 |
| Issue 模板 | 50% | 28% | <0.001 |
| 至少发过一个版本（Release） | 82% | 63% | <0.001 |
| 两种语言 | 33% | 15% | <0.001 |
| 开源协议 | 96% | 81% | <0.001 |
| 有「快速开始」 | 89% | 74% | <0.001 |
| 一步就能试用（一条命令或一个网址） | 86% | 75% | 0.016 |
| 贡献指南 | 56% | 44% | 0.020 |
| 仓库简介栏里填了官网或演示链接 | 56% | 47% | 0.073 |
| 至少 3 个 topic | 63% | 54% | 0.086 |
| 「为什么用它」或对比 | 25% | 19% | 0.16 |
| 行为准则 | 22% | 19% | 0.52 |
| README 靠前有代码块 | 76% | 80% | 0.53 |
| 展示了能做什么（功能、示例） | 73% | 72% | 0.81 |
| 仓库简介、一句话介绍、150 词以上 | 74–98% | 70–98% | ≥0.41 |
| README 开头是标题 | 87% | 94% | 0.034 |

最后一行方向相反：越受欢迎的 README，越常用居中的 logo 或横幅开头，而不是一个标题。

按档位：

| Star 数 | 仓库数 | 分数中位数 | 80 分以上占比 |
|---|---|---|---|
| 5–19 | 100 | 60 | 12% |
| 20–99 | 62 | 60.5 | 16% |
| 100–499 | 100 | 72.5 | 28% |
| 500+ | 100 | 74.5 | 39% |

README 主要用中文写的项目（362 个里有 51 个，四档都有），通过「两种语言」检查的比例远高于拉丁字母写的：57% 对 19%。

## 我们的理解

- **首屏就让人看到它在干活。** 截图或动图是我们找到的最大差距，而且发布前完全由你自己决定。
  这和评分规则一致：截图和「一步试用」本来就是分值最高的两项。
- **发帖前先补上便宜的可信信号：** 开源协议，再打一个版本（Release）。
- **剩下的别硬凑。** 徽章、社区入口、Issue 模板在 100 星以上的项目里也常见得多，但很多是有人来了之后才加的。
  这是相关，不是因果。
- **拉丁字母写的 README 里配第二语言的还很少（19%）。** 如果你要去中文或其他语言的社区发，这仍然是个空档。
- **别拿自己的 star 数去和「没有 fork 的仓库」比，也永远别买星：** GitHub 的
  [可接受使用政策](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies)
  明令禁止「rank abuse, such as automated starring or following」。

## 方法

- **抽样**：2026-10-21 在 GitHub 搜索 2026-08-01 到 2026-09-30 新建、公开、不是 fork、没归档的仓库，按 star 分四档：
  5–19、20–99、100–499、500+。每档从最近更新的 300 个结果里随机抽 100 个（随机种子 1024）。
  20–99 档排除后只剩 62 个，就全部用上。
- **排除**：模板仓库；名字以 awesome 开头的；名字或简介里有 dotfiles、homework、leetcode、course、interview、
  cheatsheet、tutorial、study-notes 这些词的；20 星以上、0 个 fork 的；以及 1 个没有 README 的。
  我们没法核实「有星没 fork」的仓库是谁点的星：GitHub 现在只让仓库管理员和协作者看 star 列表，所以这只是一个规律，不是刷星的证据。
- **打分**：[`audit.py`](../skills/launch-audit/scripts/audit.py)，和[网页体检](https://2104178150-ai.github.io/megaphone/)
  是同一套规则。语言按 README 正文的主要文字判断。
- **局限**：只是一个时间点；「最近更新」排序偏向活跃仓库；评分只看 README 的结构，不看项目好不好；
  star 衡量的是关注，不是使用。之前一次规模更小的抽样（200 个，筛选更宽松）在开源协议、发版本、徽章、第二语言、
  社区入口上结论一致，但截图的差距小得多（60% 对 51%）：几百个样本，结果仍然会晃动。

自己跑一遍（需要 GitHub token，每个仓库大约 5 次 API 调用）：

```bash
python3 scripts/study.py sample --created 2026-08-01..2026-09-30 --per-stratum 100 --out .megaphone/research/study.jsonl
python3 scripts/study.py report .megaphone/research/study.jsonl
```

我们只公布汇总数字，不公布仓库名单：要看的是规律，不是点评别人的项目。
